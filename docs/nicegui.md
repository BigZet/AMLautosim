# NiceGUI

## Результат CatBoost

Новые игры работают только на CatBoost. В редакторе нет настройки весов риска
и предварительного прогноза. После расчёта в результате показаны главные
повышающие и снижающие вклады SHAP и раскрываемый полный расчёт. Состояние
раскрытия сохраняется при перерисовке страницы. Reload читает сохранённый
результат без пересчёта модели. На мобильном экране подписи переносятся.
Организатор видит закреплённую модель в настройках. Старые варианты выбора v7
и описание временного скоринга ниже относятся к истории разработки.


Единый интерфейс на порту 8080: `/play`, `/play/login`, `/play/register`,
`/admin`, `/admin/login`, `/about`. Корень перенаправляет в `/play`.
Основной запуск — [Docker Compose](deployment.md).

## Локальный запуск

FastAPI читает `.env` через Settings; NiceGUI читает переменные процесса.
Для запуска из одного файла настроек экспортировать его в каждом терминале
(пример ниже для shell-совместимого `.env` из `.env.example`):

```bash
set -a
. ./.env
set +a
.venv/bin/python -m scripts.seed_database --wait-for-db --migrate
.venv/bin/uvicorn src.aml_workshop_simulator.api.main:app --host 127.0.0.1 --port 8000
```

В другом терминале после экспорта `.env`:

```bash
.venv/bin/python -m src.aml_workshop_simulator.ui.nicegui.app
```

`API_URL` — корень API без `/api/v1`; локально `http://localhost:8000`.
`UI_HOST` по умолчанию `127.0.0.1`, `UI_PORT` — 8080. NiceGUI не создаёт БД
или администратора. Изменения JSON требуют перезапуска API и seed каталога.

## Поведение

Участник регистрируется, ожидает начала игры, собирает и редактирует цепочку.
Preview проверяет ресурсы, автосохранение сохраняет подтверждённое состояние.
Копирование и перестановка сохраняют актуальные значения; финальная отправка
закрывает редактирование. После расчёта доступны итог, операции и рейтинг.

Организатор настраивает игру до запуска, запускает её, закрывает приём и считает
результаты одной командой. Доступны участники, блокировка с причиной, рейтинг,
аудит и перезапуск игры. Несохранённые настройки восстанавливаются в той же
вкладке; конфликт ревизии не перезаписывает чужие изменения.

UI использует только HTTP-клиент, без импорта backend-домена и чтения игровых JSON.
Общий AsyncClient передаёт `X-Session-ID` отдельно на каждый запрос.
Входы `play` и `admin` раздельны. Workspace привязан к вкладке и игре;
выход очищает workspace. Запоздалые ответы не откатывают более новое состояние.
Pending-команда сохраняет исходные метод, путь, тело и UUID для безопасного повтора.

Переподключение WebSocket повторно проверяет API-сессию. Ошибка сети показывает
возможность повтора; отзыв или блокировка требуют входа.
Сессии, cookie и том описаны в [sessions-and-cookies.md](sessions-and-cookies.md).
Проверки: [tests/README.md](../tests/README.md). Прошлые браузерные результаты:
[исторический отчёт](verification/reduced-parameters.md).

## Подготовка контрагентов v8

Компоненты редактора v8 поддерживают выбор отправителя/получателя по имени,
показывают доступность сведений, личное знакомство и число операций в предыстории.
Выбор изначально пустой; игрок явно задаёт сторону. Ручные характеристики
отправителя и «анонимный кошелёк» в этой форме отсутствуют. Административный
просмотр использует тот же снимок каталога. Интерфейс v7 сохраняет своё поведение.

Новый режим ещё не включён в обычной игре. Для локальной проверки компонентов:
`python -m scripts.preview_counterparties`, затем открыть
`http://127.0.0.1:58183/first` или `/second`. Стенд использует память процесса,
не подключает БД и не считает игровые ресурсы; его остановка удаляет тестовые
цепочки из памяти. [Полный протокол](verification/aml-counterparties-stage02.md).

## Временная шкала v8

Редактор показывает момент каждой операции и ожидание перед ней: минута,
10 минут, час или сутки. Первый шаг привязан к старту, без выбора ожидания.
После смены интервала, удаления и перестановки пересчитываются последующие
моменты. Календарная сводка отображается отдельно от остатка игрового времени.

Локальный стенд: `python -m scripts.preview_operation_timeline`, адрес
`http://127.0.0.1:58184/first`. Он считает ресурсы реальным внутренним движком,
а цепочки хранит в памяти процесса. [Браузерный протокол](verification/aml-timeline-stage03.md).

## Локальный стенд покупок (этап 04)

Запуск: `.venv/bin/python -m scripts.preview_purchases`.
Адрес: `http://127.0.0.1:58185/first`. Стенд использует компоненты редактора
и действующий расчёт, хранит данные только в памяти, не подключается к рабочей БД.
Перезапуск очищает его сценарии. Доступны добавление покупки, выбор магазина,
загрузка примера цели с покупкой и окончательная отправка на стенде.

Редактор, отправленный сценарий, ресурсная сводка и административный просмотр
раздельно показывают общие списания без комиссий и зачтённый в цель оборот.
Лимиты покупки и отсутствие зачёта в цель указаны на карточке. Это тестовый
интерфейс этапа 04; обычный выпуск теперь доступен по этапу 06.

## Профиль и предыстория (этап 05)

Черновая форма организатора v8 содержит роль клиента, доступное описание,
переключатель доступности истории и редактор событий. Для события выбираются
тип, дата со смещением, сумма и подходящая сторона. Категорию покупки определяет
сервер. После старта остаётся просмотр зафиксированных сведений.

У участника есть общий блок «Профиль и предыстория»: период, сводка поступлений
и списаний, связи сторон и таблица доступных событий. Неизвестная история
и наблюдаемый пустой период подписаны по-разному. История не добавляет деньги,
энергию, время или оборот текущей цепочке.

Локальный стенд: `.venv/bin/python -m scripts.preview_profile_history`,
`http://127.0.0.1:58186/admin`. Выберите доступную историю и зафиксируйте её;
после запуска доступны `/player/first` и `/player/second` с общим контекстом
и независимыми цепочками. Стенд хранит данные в памяти, без БД. Обычные раунды v8 теперь доступны в выпуске этапа 06. [Проверки этапа 05](verification/aml-profile-history-stage05.md).

## Полная расширенная игра (этап 06)

В «Новой игре» организатор выбирает базовые или расширенные правила.
Расширенный вариант появляется только при серверном разрешении создания.
Выбор действует на новый раунд; существующие не меняют версию. Настройка v8
включает каталог сторон, начало сценария, профиль и историю. Время суток и темп
не задаются вручную, фиксированные параметры покупки не переопределяются.

Отправленный сценарий сохраняет просмотр выбранных сторон; вкладка операций
результата показывает стороны, календарное время и стоимость ожидания.

В новых снимках работодатель доступен в зарплате и исключён из обычного входящего
перевода. Политика старых снимков сохраняется. Оценка в интерфейсе поступает
от детерминированного игрового скоринга, а не из офлайн-рубрики датасета.
[Полный проход, мобильные кадры и адрес локального стека](verification/aml-interface-balance-stage06.md).


### Исправления по результатам аудита

В форме организатора финансовые параметры доступны только для просмотра;
переключатели состава карточек заблокированы, переопределения старого риска скрыты.
Ошибки показываются с понятными подписями. Категория организации скрыта для физлиц;
известные категории переведены. Организатор видит числовой риск и «Да/Нет» для блокировки.
В пустом или незаполненном черновике показаны цель и стартовые ресурсы. «Повторить запрос»
показывается при транспортной/серверной ошибке, а не при незаполненной карточке.
SHAP использует русское форматирование чисел, кнопки копирования и удаления имеют
доступные имена. Значения вкладов и модель при этом не изменяются.
