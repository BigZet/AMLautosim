# Обучение первой модели CatBoost

Обучение и оценка выполняются отдельно от API игры, на CPU и Python 3.13.
Зависимости зафиксированы в `requirements-ml.txt`; прямые требования — в
`requirements-ml.in`. Runtime-приложение не получает CatBoost автоматически.

## Воспроизведение

```bash
docker build -f deploy/Dockerfile.ml -t aml-catboost:v1 .
mkdir -p resources/catboost_models
docker run --rm -v "$PWD:/workspace:ro" \
  -v "$PWD/resources/catboost_models:/workspace/resources/catboost_models" \
  aml-catboost:v1 python -m scripts.train_aml_catboost \
  --dataset resources/aml_dataset/release-v2-1 \
  --output resources/catboost_models/experiment-v1 --seed 20260914
docker run --rm -v "$PWD:/workspace:ro" \
  -v "$PWD/resources/catboost_models:/workspace/resources/catboost_models" \
  aml-catboost:v1 python -m scripts.evaluate_aml_catboost \
  --dataset resources/aml_dataset/release-v2-1 \
  --model resources/catboost_models/experiment-v1 \
  --output resources/catboost_models/experiment-v1/evaluation
```

Каталог обучения и каталог оценки должны быть новыми: команды отказываются
перезаписывать прошлый результат. Для повторного запуска используйте новый путь.
Исходные данные смонтированы только для чтения. Доступ к БД не нужен.

## Контракт эксперимента

Release v2-1, extractor `aml-observable-v2.6`, 84 признака, категориальный
`income_basis`. Вход сверяется с контрольными суммами и исходными сценариями.
Порядок признаков определяется схемой; лишние поля не передаются модели,
отсутствующие обязательные значения и нечисловые/бесконечные числа отклоняются.

Разбиение фиксировано: 13195 train (пять исходящих переводов), 2934 validation
(шесть), 3871 test (восемь). ID, метки, объяснения и прежний скоринг не являются
признаками. 24 неразмеченные проверочные цепочки не превращаются в независимый
размеченный test; известные пары используются лишь для диагностики поведения.

12 моделей: depth 4/6/8 × l2 3/10 × RMSE или Quantile alpha=0.65.
До 2000 итераций, learning rate 0.05, 4 CPU-потока. Остановка после 100 итераций
без улучшения validation MAE, сохранение лучшей итерации. Сначала выбираются
модели, прошедшие критерии, затем минимальная MAE и меньшее число деревьев.
Если проходящих нет, диагностический выбор минимизирует число высокого риска
ниже 50, долю занижений >15, MAE и число деревьев в указанном порядке.

`selection.json` фиксируется до test. Два дополнительных seed и повтор исходного
проверяются на validation; основная модель не заменяется. Команда оценки только
загружает `.cbm` и предсказывает, не вызывает обучение. Повторная оценка той же
модели допустима для проверки отчёта, но не делает просмотренный test новым.

## Критерии и артефакты

На validation и test нужны MAE ≤5, ошибка ниже константной медианы train,
не более 5% занижений >15 среди целей ≥75 и ни одного прогноза <50 среди целей ≥75.
Применяется ограничение прогноза 0–100; метрики до ограничения тоже сохраняются.
Проверки повторного обучения, загрузки и перестановки признаков имеют допуск 1e-8.

Модель и схема, параметры всех кандидатов, кривые обучения, версии пакетов,
контрольные суммы, seed-проверки и сведения о воспроизводимости находятся в
каталоге эксперимента. Оценка сохраняет прогнозы, метрики, разрезы с размером
группы, крупнейшие ошибки с объяснениями, пары, графики и `MODEL_CARD.md`.
Важность признака не интерпретируется как причинный эффект.

Тесты из `tests/ml` требуют ML-окружения и не добавлены в обычный unit-набор:

```bash
docker run --rm -v "$PWD:/workspace:ro" aml-catboost:v1 \
  python -m pytest -q -p no:cacheprovider tests/ml
```

Три семейства родителей и синтетическая рубрика ограничивают выводы.
Соответствие рубрике не подтверждает эффективность реального AML.
При провале критериев модель остаётся диагностической; разметка и разбиение
не меняются ради улучшения результата. Интеграция требует отдельного этапа.
