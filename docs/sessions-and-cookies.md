# Сессии и вход

FastAPI выдаёт непрозрачный `session_id` через `POST /api/v1/auth/login`.
Клиент передаёт его в `X-Session-ID`. В PostgreSQL хранится только SHA-256
идентификатора, срок действия, пользователь, audience и сведения об отзыве.

- `audience=play` доступна участнику, `audience=admin` — администратору.
- `GET /auth/session` проверяет срок, отзыв, блокировку пользователя и возвращает
  текущую учётную запись. Чтение не обновляет БД.
- `DELETE /auth/session` отзывает текущую сессию; повтор безопасен.
- Блокировка участника отзывает его сессии в той же транзакции.
- После снятия блокировки требуется новый вход.
- Новая игра сохраняет аккаунты и сессии.

Пароли длиной 10–128 символов хешируются `bcrypt_sha256`, чтобы длинный пароль
не усекался ограничением bcrypt. Вычисления выполняются вне основного цикла
запросов. Неудачные входы учитываются под блокировкой строки пользователя;
после установленного числа попыток действует временный запрет входа.

Инспектора сессий, ротации, сбора IP, User-Agent, языка браузера и обновления
`last_seen_at` в текущем API нет. Заголовки браузерных метаданных не требуются.

Хранение идентификатора в браузере относится к следующему этапу Streamlit.
Текущие UI ещё используют старые контракты. При обновлении нужно сохранить
раздельные административную и игровую сессии, восстановление входа после
обновления страницы и удаление cookie при выходе. План —
[streamlit-next-step.md](streamlit-next-step.md).

Сырой идентификатор сессии и пароль нельзя писать в логи. Истёкшие и отозванные
строки не дают доступа; автоматическая фоновая очистка сейчас не реализована.
