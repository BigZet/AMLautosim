# Безопасность ядра

FastAPI проверяет доступ независимо от UI. Собственный сценарий определяется
по пользователю сессии; клиент не выбирает владельца. Административные команды
требуют одновременно роль `admin` и audience `admin`.

Сессии и пароли описаны в [sessions-and-cookies.md](sessions-and-cookies.md).
Сырые session ID и пароли не сохраняются в БД и не должны попадать в логи.
Ответы API получают `Cache-Control: no-store` и идентификатор запроса.
Необработанная ошибка возвращает общее сообщение; traceback остаётся в логе.

## Целостность игры

- Сервер проверяет карточки, параметры и игровые ограничения.
- Автосохранение может содержать ещё не готовую цепочку; окончательная отправка
  требует полной валидности и не допускает последующих изменений.
- Настройки и снимок карточек неизменяемы после запуска.
- Закрытие приёма фиксируется до расчёта и не откатывается при ошибке скоринга.
- Блокировки БД и ревизии защищают от конкурентных записей.
- Неотправленные сценарии видит только владелец; закрытие приёма удаляет их.
- Новая игра удаляет прежние игровые данные, сохраняя аккаунты и сессии.

## Развёртывание

Для локальной проверки API и PostgreSQL привязаны к loopback. При внешнем
развёртывании нужны TLS, собственные секреты и ограниченный доступ к БД.
Bootstrap-пароль из примера предназначен для разработки.

Streamlit обновляется отдельно: правила cookie, отсутствие общих заголовков
авторизации между пользователями и восстановление сессии нужно проверить
на следующем этапе. Не считать текущий UI совместимым с новым API.
