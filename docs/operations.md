# Эксплуатация

Все команды выполняются из корня проекта с настроенной `.env`.
Для проверки используйте отдельный Compose-проект, собственные порты и тома.

## Подготовленный пакет AML-классификатора

`AML_MODEL_PATH` сохраняет назначение пакета регрессора v8. Отдельная переменная
`AML_PROBABILITY_MODEL_PATH` указывает на неизменяемый каталог классификатора v10.
Текущий Compose использует принятый `aml-game-organizer-settings-v1` для новых
v10-раундов. `EXPANDED_ROUNDS_ENABLED=false` останавливает создание новых игр,
сохраняя обслуживание существующих. Разрешённые настройки меняются до старта.

Online-загрузчик требует принятый пакет с checksum, протоколом, доказательствами
оценки и allowlist профилей/каналов. Offline candidate допускается только явно
в инструментах исследования. Отсутствующий пакет, несовместимый контекст или
изменённый pin приводят к отказу, а не к пересчёту старой моделью.

При выпуске следует сохранять пакеты всех начатых раундов. Откат закрывает новые
v10-игры; начатые требуют своего закреплённого пакета. Уже завершённые результаты
читаются из БД. Текущие инфраструктурные тесты не являются приёмкой релиза.

## Состояние и диагностика

```bash
docker compose ps
docker compose logs --tail=100 api ui
curl --fail http://127.0.0.1:8000/health/ready
```

API liveness не обращается к БД; readiness проверяет соединение и ревизию Alembic.
Пакет CatBoost проверяется при старте API, readiness также сообщает его identity.
UI liveness подтверждает только работу UI-процесса. Вход и игровые команды
дополнительно проверяют взаимодействие UI с API.
Ошибки API имеют `request_id`; не публикуйте секреты, сессии или полный `.env`.

`SESSION_TTL_MINUTES`, `LOGIN_MAX_FAILED_ATTEMPTS` и `LOGIN_LOCKOUT_MINUTES`
должны быть целыми числами больше нуля. Нулевые и отрицательные значения
отклоняются при старте; они не означают отключение защиты входа.

## Обновление

Сначала сделайте резервную копию. Остановите UI и API, обновите исходники и соберите
образ, затем запустите стек. БД продолжает работать.

```bash
docker compose stop ui api
docker compose build
docker compose up -d --wait
```

Команда API применяет миграции и seed. Повторный seed сохраняет пароль
существующего администратора и снимок текущей игры. Новые значения каталога
применяются к новой игре. Изменение формата снимка требует отдельной процедуры
миграции или согласованного сброса; текущая очистка формат не меняет.

## Резервная копия

Для согласованной копии БД и UI остановите оба приложения. Каталог `.backups`
исключён из Git и образа. Копию `.env` храните отдельно с ограниченным доступом.

```bash
mkdir -p .backups
chmod 700 .backups
docker compose stop ui api
docker compose exec -T db sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > .backups/database.dump
docker compose run --rm --no-deps -T ui tar -C /home/app/nicegui -czf - . > .backups/nicegui.tar.gz
docker compose up -d --wait
```

Проверьте код завершения каждой команды и перенесите копии на отдельный носитель.
Архив UI содержит API-сессии; обращайтесь с ним как с секретом.

## Восстановление

Сначала проверьте восстановление в отдельном Compose-проекте с новой БД,
собственными портами, пустыми томами и тем же секретом NiceGUI.
Остановите приложения целевого проекта; БД должна быть запущена.
Следующая команда заменяет данные целевой базы из копии:

```bash
docker compose stop ui api
docker compose exec -T db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists --no-owner --exit-on-error' < .backups/database.dump
docker compose run --rm --no-deps -T ui tar -C /home/app/nicegui -xzf - < .backups/nicegui.tar.gz
docker compose up -d --wait
```

Архив UI восстанавливайте в пустой том, чтобы не оставались более новые сессии.
После восстановления проверить readiness, вход обеих ролей, состояние игры,
цепочку и рейтинг. Для отката версии нужны совместимый образ и резервная копия
до обновления; откат только образа не откатывает схему и каталог.

## Игра и учётные записи

Штатный перезапуск игры выполняется организатором в UI: удаляет игровые данные,
сохраняет пользователей и сессии, создаёт новый `draft`.
`python -m scripts.seed_database --migrate --reset-game` — отдельный разрушающий
сброс при остановленных API/UI; обычный запуск его не выполняет.
При ошибке скоринга приём остаётся закрыт; после исправления причины повторить
расчёт в UI. Блокировка участника отзывает сессии; разблокировка требует входа.
