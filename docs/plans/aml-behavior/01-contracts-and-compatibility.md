## Цель и границы

Создать версионированный фундамент расширенной игры, сохранив прежнее поведение существующих раундов. На этом этапе новые возможности не включаются для обычных раундов.

## Предварительные условия

- Прочитать текущие контракты сценария и конфигурации, нормализацию, движок и хранение JSON-снимков.
- Зафиксировать исходные проверки и существующее расхождение UI-теста, описанное в общем плане.

## Зафиксированные решения

- Новые каталог и история хранятся в существующих JSON-снимках; отдельные таблицы для них не создаются.
- Обработка выбирается по версии сохранённого снимка. Неизвестная версия отклоняется явно.
- Старые поля, расчёты и сохранённые результаты не переосмысляются и не переписываются.
- Незавершённый новый контракт доступен только тестовым конфигурациям до завершения этапа 06.

## Последовательность реализации

1. Сохранить эталонные старые конфигурации, цепочки, ресурсные расчёты и результаты скоринга в тестовых fixtures.
2. Определить новую версию снимка и границы совместимой обработки; зафиксировать решение в документации контрактов.
3. Описать типизированные места для каталога сторон, профиля, истории, интервалов и целевого оборота.
4. Обновить сериализацию и чтение снимков без автоматического заполнения старых раундов вымышленными данными.
5. Ввести серверную проверку готовности новой версии перед созданием и запуском раунда; скрытие пункта UI не заменяет проверку API.
6. Добавить интеграционные проверки сохранения и загрузки обеих версий.

## Данные, API и интерфейс

- Данные: версия конфигурации и расширение JSON-снимка; прежняя версия продолжает читаться.
- API: версия определяет допустимые поля и обязательность новых данных; неподдерживаемые версии возвращают понятную ошибку.
- Интерфейс: обычный организатор пока не может выбрать новую версию.

## Автоматические проверки

- Результаты старых fixtures совпадают по балансу, времени, энергии, цели и скорингу.
- Сериализация → сохранение в PostgreSQL → чтение сохраняет значения и типы обеих версий.
- Неизвестная версия, неполный новый снимок и попытка обойти запрет запуска отклоняются без изменения данных.

Команды брать из [матрицы проверок общего плана](README.md#verification). Новые целевые тесты и точные команды записать в фактические результаты после их появления.

## Ручной сценарий

1. Открыть старый тестовый раунд, загрузить сохранённую цепочку и сравнить результаты с исходными.
2. Проверить, что новая версия недоступна для обычного запуска, в том числе прямым запросом API.

## Отключение при ошибке

Оставить новый режим недоступным для создания и запуска. Сохранить совместимый код чтения уже записанных тестовых снимков; не понижать их версию и не переписывать содержимое.
