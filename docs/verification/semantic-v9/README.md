# Исправления v9: подготовка к согласованию рубрики

Дата: 2026-09-15. Статус: интерфейс и подготовительный контракт реализованы; массовая разметка, обучение и выпуск v9 ожидают согласования восьми примеров.

[Исходный аудит](../semantic-interface-audit/README.md) · [Восемь оценок](../../../resources/aml_dataset/review-v9-1/README.md) · [Полные цепочки](../../../resources/aml_dataset/review-v9-1/cases.json)

## Что изменено

- `/play/profile` — отдельная страница профиля и истории; навигация использует прежнее хранилище черновика. `/play/results` открывает результаты после расчёта.
- Добавление через одну верхнюю кнопку; новые операции отображаются сверху. API-массив и выполнение остаются хронологическими. Карточки раскрываются для редактирования; перестановка вынесена в «Порядок выполнения».
- Сводка ресурсов закреплена, дополнительные лимиты раскрываются отдельно. Рейтинг показывает числовой риск, итог и ресурсы; добавлено раскрытие формулы. SHAP показывает направление и полосы вкладов; сохранённые объяснения не переписываются.
- Контракт v9 различает банковский перевод, платёжного посредника, вывод с биржи и P2P. Проверки ролей и зависимых полей выполняет сервер. Только зарплатный реестр, обычные исходящие переводы — людям, покупка — торговой стороне.
- В истории v9 предусмотрены неизвестные тип поступления, страна банка, канал и основание зарплаты. Для организаций не допускается личное знакомство; ID сохраняет связь реквизитов при неполных личных сведениях.
- Extractor `aml-observable-v4.0` исправляет концентрацию внутри суммы переводов, добавляет признак наличия переводов, новые типы поступлений, применимость отношений и доступность полей истории.
- Проект рубрики `educational-risk-v3-review-1` удаляет нижнюю опору 45, сохраняя вклад интенсивности до 10 и прочие численные ограничения. Уточнено название недостаточной фоновой активности.

Для финансовой симуляции v9 используется внутренняя проекция на сохранённые ресурсные правила v8: это сохраняет суммы, комиссии, энергию и время. Она не используется для оценки v9 старой моделью. Новые наблюдения хранятся в v9; публичные поля карточек и детали поступлений описывают новые смыслы. Исторические неизвестные сведения не восстанавливаются из этой проекции.

`require_new_round_allowed` отклоняет новые v9-раунды. Текущий модельный адаптер также не принимает v9. Разрешение запуска и новый адаптер будут добавлены только после обучения, проверки SHAP и выпуска нового пакета.

## Согласование

Все восемь примеров допустимы и достигают 400 000 ₽. В JSON сохранены снимки, шаги, признаки и полное разложение рубрики. В `review-status.json` — статус `pending` и SHA256 рубрики/примеров. Проверка допуска массовой генерации требует явного `approved` с совпадающими хешами; ожидание ответа не считается согласованием.

Биржа и P2P имеют новый смысл, поэтому прежняя оценка для них не вычисляется. Для остальных сравнений одновременно действуют изменения концентрации и опоры — таблица не объявляется изолированным экспериментом одного признака.

Команда воспроизведения восьми примеров:

```sh
.venv/bin/python -m scripts.aml_dataset.semantic --output resources/aml_dataset/review-v9-1
```

Новый протокол сохранён в `config/ml/behavior-v3-protocol.json`: seed данных 2026091505, основной модели 2026091506, дополнительных запусков 2026091507/08. Массовый генератор и обучающий запуск v9 ещё не выполнены; файл протокола не является результатом эксперимента.

## Проверки и окружение

- Отдельная локальная `.venv`, Python 3.13.15, зафиксированные зависимости приложения и ML. Проверки использовали CatBoost 1.2.10.
- Docker Compose-проект `aml-v9`, отдельная PostgreSQL и тома. Новые пароли находятся только в игнорируемом `.local-run/v9/stack.env`; прежние контейнеры и данные не удалялись.
- Unit v9: 38 проверок ролей, ресурсов, истории, концентрации, неизменности исходников v8 и допуска разметки прошли.
- HTTP v9: матрица 32 сочетаний поступления/стороны, preview, autosave, reload, метаданные и запрет старта проверены на изолированной тестовой БД. V9-раунд установлен непосредственно тестовой фикстурой; обхода ограничения запуска в приложении нет.
- Модельная регрессия: 44 проверки v9 и прежнего пути с SHAP прошли. Это не оценка ещё не обученной модели v9.
- Первый общий прогон: 445 passed / 1 failed. Причина — старый UI-тест выбирал последнюю по ID форму вместо новой верхней карточки; тест обновлён с сохранением проверок сценария. Повторный целевой прогон: 65 passed, включая полный пользовательский путь и переход на профиль с возвратом к сохранённой цепочке.
- Итоговый общий прогон: **453 passed**, 2 предупреждения, 255,55 с; [JUnit](pytest.xml). После уточнения подписи биржи и сохранения лимита истории повторно прошли 39 профильных тестов.
- Все **4 413** прогноза v8 совпали точно (максимальная ошибка 0); максимальная ошибка аддитивности SHAP — `2.274e-13`. Первые 100 цепочек рассчитаны за 3,95 с, весь набор — за 181,57 с. [Численный отчёт](v8-regression.json). Измерение выполнено локально, оно не заменяет контейнерный замер будущей модели v9.
- Финальная пересборка API/UI успешна: API readiness сообщает подключённую БД, миграции `head` и прежнюю модель v8; UI liveness возвращает `ok`. Ruff проходит. [Сводка](checks.json).

Команды проверок:

```sh
.venv/bin/python -m pytest -q tests/unit tests/api tests/ml/test_model_scoring.py
.venv/bin/python -m scripts.verify_model_integration --dataset resources/aml_dataset/behavior-v3/release --predictions resources/catboost_models/experiment-v2/evaluation/predictions.csv --output .local-run/v9/v8-regression.json
.venv/bin/ruff check src scripts/aml_dataset/semantic.py tests/unit/test_semantic_v9.py tests/api/test_semantic_v9.py
docker compose --env-file .local-run/v9/stack.env -p aml-v9 up -d --build api ui
```

Для API-тестов задаётся `TEST_ADMIN_DATABASE_URL` отдельной тестовой PostgreSQL; реальные локальные реквизиты не публикуются. Повторное сравнение требует нового пути вывода. Ссылка на UI тестового стека: `http://localhost:58809` (пока действующие раунды v8).
