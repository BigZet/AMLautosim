# Этап 01: контракты и совместимость

Дата: 13 сентября 2026 года. Статус: критерии этапа 01 выполнены.
База рабочей копии: `be4cb32`; изменения не закоммичены. До работы уже существовали
прототип датасета, планы и изменение формы `participant.py`; они не относятся
к реализации контрактов этого этапа.

## Что реализовано

- Контракт v7 остаётся рабочим по умолчанию, включая конфигурации старых клиентов
  без явно переданного `schema_version`.
- V8 имеет отдельные типизированные модели и явный выбор при чтении снимка.
  Для v8 номер версии обязателен; наличие `behavior` не включает новую версию неявно.
- В `behavior` зарезервированы каталог сторон, профиль, история, временная шкала
  и политика целевого оборота. Суммы сохраняются десятичными строками, временные
  метки требуют часовой пояс, JSON-ключи интервалов корректно проходят round-trip.
- Новые данные сохраняются в существующем JSON-снимке; миграций и новых таблиц нет.
- `freeze_game_config` сохраняет выбранную версию вместо принудительной записи v7.
- Создание/обновление/запуск v8 отклоняются сервером с `409 round_contract_not_ready`.
  Клиентского или переменного окружения обхода нет. Пока доступны только
  внутренние тестовые построение, сохранение и чтение таких снимков.
- Ресурсный движок и скоринг не интерпретируют v8 как v7; попытка скоринга
  отклоняется до закрытия приёма, удаления черновиков и изменения статуса.
- Неподдерживаемые версии отклоняются; неполные DTO не проходят валидацию.
  При прямом чтении неподдерживаемого снимка используется `round_contract_unsupported`.
- Для тестового v8 состояния `can_edit`, `can_submit`, `accepts_changes` ложны.

Это фундамент данных, а не реализация контрагентов, ожидания, покупок или анализа
истории. Семантическая проверка ссылок сторон, временного окна истории и новые
формулы выполняются в этапах 02–05. Зарезервированный тип шага v8 ещё не принимается
эндпоинтами изменения сценария.

## Контроль старого поведения

До изменения движка сохранены три fixture-цепочки: `transfers`, `mixed`,
`incoming_funding`. Файл `tests/fixtures/contracts/legacy-v7.json` содержит исходный
снимок карточек и правил, канонические шаги, полные ресурсы, нарушения, объяснения
риска и значения рейтинга. Тесты сравнивают их с новым кодом и проверяют отсутствие
изменения исходного снимка. Ожидания не вычисляются заново внутри теста.

## Окружение

- macOS; установленная `.venv`: Python 3.12.14.
- Отдельный одноразовый контейнер `postgres:16`, имя `aml-contract-stage01-test`.
- PostgreSQL опубликована только на loopback, случайный порт данного запуска 50184.
- API-тесты создавали и удаляли собственные `aml_test_<uuid>` базы.
- Для браузерной проверки создана отдельная БД `stage01_walkthrough` в том же
  тестовом контейнере; API 58181, NiceGUI 58182, хранилище UI в `/tmp/aml-stage01-ui`.
- Проверка интерфейса: Safari через UI automation. Использовались только специально
  созданные тестовые учётные записи. Рабочая игра и её БД не изменялись.

## Контрольный проход через браузер и HTTP

1. Созданы тестовый раунд v7 и участник; через HTTP сохранена исходная
   `incoming_funding`-цепочка. Ресурсный снимок полностью совпал с fixture.
2. В Safari открыт экран организатора: активный раунд и сохранённая конфигурация
   `schema_version=7`, четыре карточки, `game-rules-v5`; новый режим не предлагается.
3. В отдельной вкладке открыт участник. Загружены девять сохранённых операций:
   баланс 7 950,00 руб., энергия 9, время 1, осталось пять шагов; цель 400 000 руб.
   достигнута, состояние «Сохранено».
4. Выполнен reload страницы; те же операции и значения восстановились.
5. Через HTTP выполнены окончательная отправка и скоринг. В браузере показаны:
   итог 58,84; риск 21,00; сбережённые ресурсы 21,39; первое место.
6. Прямой обход запрета v8 проверен API-тестами, включая атомарность отказа.
