## Проверка интерпретаторов

Запуск сделан из корня репозитория через `.venv/Scripts/python.exe` с `PYTHONUTF8=1`.

| Вызов / источник | Реальный интерпретатор | Результат |
|---|---|---|
| Текущий процесс | `.venv/Scripts/python.exe`, Python 3.13.15 | ML-пакеты установлены |
| `shutil.which("python")` | Глобальный `Python312/python.EXE`, Python 3.12.10 | Это результат поиска в PATH, а не фактически запущенный child |
| `subprocess.run(["python", ...])` | Базовый uv `cpython-3.13-windows-x86_64-none/python.exe`, Python 3.13.15 | `pip freeze`: код 0, **0 строк** |
| `subprocess.run([sys.executable, "-m", "pip", "freeze"])` | `.venv/Scripts/python.exe`, Python 3.13.15 | Код 1: **No module named pip** |

Важное уточнение: первоначальная гипотеза о запуске глобального Python **3.12.10** непосредственно из этих функций в данной среде **не подтвердилась**. Реальный дочерний процесс — базовый uv Python **3.13.15 вне `.venv`**. Совпадение версии Python не означает совпадения установленных пакетов.

Простая замена строки `"python"` на `sys.executable` устранит выбор чужого интерпретатора, но **сама по себе не исправит текущий Windows-сценарий**: в `.venv` нет модуля `pip`. README описывает создание `.venv` через `uv venv` и установку через `uv pip install` (`README.md:45–53`); наличие pip внутри такого окружения код не обеспечивает.

## Связь с итоговыми артефактами

- `behavior_model.train` записывает `reproducibility.json` и `model-checksum.json` (`behavior_model.py:523–532`). `catboost_pipeline.train` записывает checksum бинарника (`catboost_pipeline.py:362`) и проверку повторного обучения / reload / порядка признаков (`catboost_pipeline.py:410–422`). Эти проверки не сопоставляют записанные зависимости с активным процессом. Следовательно, ошибочный `environment.txt` не обнаруживается предусмотренными проверками воспроизводимости.
- Финальный `manifest.json` создаётся отдельно в `scripts/package_behavior_model.py:60–82`, обновляется после inference-проверки на строках 184–186. Manifest содержит хеши модели/схемы, датасета, inference source и ссылку на метрики. `environment.txt`, `environment.json` и их хеши туда не входят; они также не копируются в финальный пакет (`package_behavior_model.py:58–59`, `187–197`). Это ограничение provenance финального пакета: он не исправляет и не проверяет выявленное расхождение. Отдельный дефект корректности inference из этого не следует.
- Исторические `resources/catboost_models/experiment-v1/environment.*` и `experiment-v2/environment.*` содержат Linux / Python 3.13.15 и **81 строку** зависимостей, включая CatBoost/NumPy/pandas. Проверка **не доказывает**, что provenance уже сохранённых Linux-экспериментов ошибочен. Подтверждён дефект нового запуска в текущем Windows-окружении.

## Последствия и рекомендации

Пустой либо чужой freeze не позволяет восстановить фактическое окружение нового эксперимента и может скрыть различие версий ML-библиотек. При недоступном `python`/pip весь запуск падает на подготовке metadata, даже если необходимые для обучения библиотеки установлены.

Рекомендуется собирать зависимости именно активного интерпретатора: через `sys.executable` с гарантированным наличием pip либо через поддержанный вариант без встроенного pip, например установленный `uv pip freeze --python <sys.executable>` или metadata текущего процесса. Отдельно сохранять `sys.executable`, `sys.prefix`, версии критичных ML-пакетов и проверять полноту provenance. Сбор окружения стоит проверить до создания неизменяемого output-каталога либо предусмотреть явный статус незавершённого запуска. Для переносимого финального пакета полезно включить training provenance и его хеши.

Исправления production-кода, тестов, зависимостей и существующих артефактов **не выполнялись**. Полное обучение не запускалось; его качество или воспроизводимость на другом оборудовании этим узким аудитом не проверялись.
