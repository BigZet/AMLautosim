Отсутствуют принятый полный эксперимент и production-пакет. Скрипт

производительности релиза, браузерная проверка и 25 независимых demo-цепочек.
Ссылки на новые v10-игры и креды демонстрации пока не созданы. Создание/старт v10
остаются закрыты; настройка пути к пакету не снимает этот запрет.

## Воспроизведение выполненных проверок

В активированном Python-окружении проекта, из корня рабочей копии:

```powershell
$env:PYTHONUTF8 = '1'
python -m ruff check src scripts tests migrations
python -m pytest -q tests/unit tests/ml
python -m pytest -q tests/api/test_aml_integration.py tests/api/test_model_integration.py::test_model_round_atomic_retry_and_no_early_explanation
```

Для последней команды `TEST_ADMIN_DATABASE_URL` должен указывать на отдельный
тестовый PostgreSQL с правом создания временных БД. Секрет передаётся через
окружение. Тестовая инфраструктура создаёт и удаляет собственную БД.

После получения принятого датасета и пакета verifier запускается отдельно;
путь отчёта должен быть новым и находиться вне каталогов датасета и пакета:

```powershell
python -m scripts.verify_aml_integration --dataset resources/aml_dataset/aml-v1/release --package resources/catboost_models/aml-classifier-v1 --output .local-run/aml-verification.json
```

Его успешный отчёт подтверждает только совпадение offline/runtime по полному
зафиксированному test и последовательное время объяснений. Он не заменяет
независимую демонстрацию, проверку восстановления и браузерную проверку.

Полный критерий завершения: [план внедрения](../../superpowers/plans/2026-09-16-fraud-probability-classifier.md),
включая все требования Task 3–8, а не только перечисленные здесь зелёные проверки.

## Подготовка независимой демонстрации

`scripts/aml_demo_casebook.py` проверяет состав пяти раундов: по две законные,
две AML-цепочки и одной неоднозначной. Все участники каждого раунда используют

переименование профиля само по себе не считается разнообразием.

Перед фиксацией helper проверяет точную привязку независимого review, полный
игровой движок и отсутствие общих групп с переданным development-корпусом.
Сохраняются исходный casebook, записи, граф связей, протокол и hashes.
Дальнейшие изменения development требуют повторной проверки независимости;
дата локального файла сама по себе не доказывает отсутствие предыдущего обучения.

```powershell
python -m scripts.aml_demo_casebook --casebook <reviewed-25-casebook.json> --development <all-development.jsonl> --output .local-run/aml-demo-frozen-v1
```

Код принят после независимого review; 19 целевых тестов прошли в обычном режиме
и с `python -O`. Успешная проверка записи файлов использует настоящие ранее
проверенные development-кейсы с изолированной заменой только проверки состава;
это тест ввода/вывода, **не готовая независимая демонстрация**.

Реальные 25 новых кейсов теперь созданы: актуальная версия `demo-draft/v3`,
независимый AI review импортирован в `demo-reviewed/v3`, состав до обучения
сохранён в `resources/aml_dataset/aml-v1/demo-frozen/v2`. Разметка: 10 законных, 10 AML и
5 unresolved; это автоматизированная проверка, не человеческая AML-экспертиза.
Повторный полный аудит с 1 096 development-записями не выявил общих компонентов.
Результат и точные хеши: [demo-freeze-audit-v2.json](demo-freeze-audit-v2.json).
Пять раундов имеют пять общих историй, а не 25 независимых историй.

Перед обучением `scripts/aml_demo_training.py` заново проверяет привязку review,
целостность freeze и независимость от полного окончательного корпуса. Проверенные
байты демопримеров и воспроизводимая квитанция сохраняются в артефакт обучения
до первого fit, включая baseline. Калибровка и упаковка повторяют эту проверку.

python -m scripts.train_aml_classifier --dataset <release-dataset> --protocol <protocol.json> --frozen-demo resources/aml_dataset/aml-v1/demo-frozen/v2 --output <new-training-directory>

изолирует preflight; проверка файлов отдельно использует настоящий движок,

API-запуск, браузер, ссылки, доступ организатора и фактические вероятности

## Подготовленный запуск пяти экземпляров

`scripts/create_aml_demo.py` требует принятый production-пакет, соответствующий
датасет и точный состав demo, привязанный до обучения. Скрипт создаёт пять игр
и 25 аккаунтов, отправляет все цепочки, повторяет скоринг, сверяет сохранённые
результаты и рейтинги. Неудачные ожидаемые диапазоны сохраняются в отчёте;
они не заменяются другими примерами. Частичный сбой оставляет журнал и доступ
к уже созданным играм. Повторное использование выходного каталога запрещено.

Для каждой игры нужны отдельные PostgreSQL, API и UI: действующая модель
приложения поддерживает один текущий раунд. Override
`deploy/docker-compose.aml-demo.yml` добавляется к корневому `docker-compose.yml`.
Он требует уникальные `AML_DEMO_PROJECT`, `POSTGRES_PORT`, `API_PORT`, `UI_PORT`
и абсолютный `AML_DEMO_PACKAGE`; пакет монтируется только для чтения, все порты
слушают loopback. Остальные обязательные секреты — как в основном compose.
Хранить пять файлов окружения следует в `.local-run`, с одним организатором
и отдельными паролями БД и NiceGUI secrets для каждого экземпляра.

Инициализация использует `seed_database --no-demo-round`: создаёт карточки
и организатора, оставляет текущую игру без изменений, а на пустой БД не создаёт
старый v8-раунд. Флаг несовместим с `--reset-game`. Проверены пустая БД,
повторная инициализация и сохранность существующего раунда/аудита на настоящем
PostgreSQL. Конфигурация пяти compose-проектов проверена через `docker compose
config` (Compose v5.5.1); это ещё не запуск контейнеров с принятой моделью.

После выпуска модели и подготовки пяти экземпляров:

```powershell
# Секрет организатора предварительно передан через окружение.
python -m scripts.create_aml_demo --dataset <release-dataset> --package <accepted-package> --casebook resources/aml_dataset/aml-v1/demo-frozen/v2 --output .local-run/aml-demo-release --api-url http://127.0.0.1:58500 --api-url http://127.0.0.1:58501 --api-url http://127.0.0.1:58502 --api-url http://127.0.0.1:58503 --api-url http://127.0.0.1:58504 --ui-url http://127.0.0.1:58580 --ui-url http://127.0.0.1:58581 --ui-url http://127.0.0.1:58582 --ui-url http://127.0.0.1:58583 --ui-url http://127.0.0.1:58584
```

Порядок URL соответствует `casebook.json.rounds`. Скрипт проверяет пустоту всех
пяти экземпляров до первой записи. Выходы: `index.html`, `report.json` и приватный
`private-access.json`. Не публиковать выходной каталог целиком: он содержит
пароли. Код выхода 2 означает, что игры созданы, но ожидаемые диапазоны не прошли.

При переносе исходного контекста API добавляет отсутствовавшие необязательные
поля истории со значением `null`. Скрипт проверяет равенство нормализованных
конфигураций, семантики карточек и всех 146 признаков; в отчёте сохраняет исходный
и серверный хеши контекста. Замена первичных ключей карточек и представления
контекста не изменяет замороженные примеры или значения прогнозов.

Итоговая проверка инфраструктуры: **25 тестов прошли в Windows и Linux**, включая
создание всех пяти контекстов, отправку 25 цепочек, хранение результатов и повторный
скоринг на настоящем PostgreSQL. Скорер в этих API-тестах фиксированный тестовый;
допуск v10 заменяется только внутри теста. Отдельный тест проверяет отказ реального
малого CatBoost-пакета в production loader. 13 unit/ML тестов также прошли с `-O`.
Независимое review отклонило 200 подмен результата и три подмены идентификаторов.
Версии, хеши и пределы проверки: [demo-orchestration-checks.json](demo-orchestration-checks.json).
Это не подтверждение качества модели или успешного попадания demo в диапазоны.

## Текущая ёмкость генератора

Первый источник с 6 090 наблюдениями дал 1 270 компонентов, но добавление
реальных наличных расчётов объединяет часть ранее различимых историй.
Полная повторная группировка `population-draft/v1/cash-complete-closure`
содержит 7 617 записей и 1 186 компонентов: **1 156 компонентов новой популяции**,
25 старого development-корпуса и 5 demo. Пересечений с demo не обнаружено.
Следовательно, исторический выбор `selection-v2` из 1 200 групп больше
не является действующим подтверждением необходимого объёма.

Исправления хозяйственных оснований ролей независимо проверены для всех
7 917 кандидатов `role-candidates-v3`. Это подтверждает основания ролей,
но не заменяет полную разметку, новые независимые контрольные наборы и
достижение 1 200 групп после всех объединений. Следующий пилот расширяет
фактические истории исполнения договоров; обучение итоговой модели не начато.
