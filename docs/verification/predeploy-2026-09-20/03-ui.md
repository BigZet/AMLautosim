# 3. UI участника и организатора

## Результат

[Автоматические проверки](ui-tests.log): **39 passed, 2 failed**, 28,95 с ([JUnit](ui-tests.xml)). Два падения вызваны поиском удалённого текста «Добавить операцию»; браузерный сценарий проверен отдельно на действующих кнопках.

Проверено текущее приложение в изолированном Linux Compose, Chrome на Windows: desktop 1440×1000 и mobile viewport 390×844. Это эмуляция ширины, не тест физического телефона. Сценарий до результата работает на пакете, фактически включённом в Docker. Подмена его текущим локальным пакетом не выполнялась: DEP-01 остаётся блокером.

## Поведение и доказательства

- Вход участника, ожидание, вход организатора и старт: [ожидание](ui-waiting-desktop.png), [организатор](ui-admin-draft-desktop.png), [лог подтверждённого старта](browser-start-confirmed.log).
- Редактор: добавление зарплаты и перевода, сумма, смена получателя с немедленным изменением заголовка, сворачивание и доступные действия копирования/удаления, автосохранение и восстановление после reload. [Лог](browser-editor.log), [действия](ui-editor-actions-desktop.png), [мобильный редактор](ui-editor-mobile.png).
- Профиль и ограничения открываются; горизонтального переполнения на проверенной ширине нет. [Профиль](ui-profile-mobile.png), [ограничения](ui-limits-mobile.png).
- Для полного расчёта девять шагов установлены через API из контрольной цепочки; все девять вручную в UI не вводились. Отправка и подтверждение выполнены в браузере. [Подготовка](browser-chain-fixture.log), [ожидание после отправки](ui-submitted-mobile.png).
- Скоринг запущен организатором через UI. Участник автоматически перешёл к результату; навигации нет и при прямом посещении /play/profile, /play/limits, /play/results. Reload сохраняет результат. [Лог](browser-results.log), [desktop](ui-results-desktop.png), [mobile](ui-results-mobile.png).
- Расчёт балла открыт постоянно. Отображение до сотых проверено по разметке/форматированию и снимкам; вычислительная точность рассмотрена в отчёте скоринга. Во всех трёх SHAP-окнах 28 строк, проценты в заголовках отсутствуют, сортировка вклада меняет порядок на обратный. Полосы вкладов видны. [SHAP](ui-shap-mobile.png).
- В успешных браузерных прогонах редактора/результатов console error и pageerror не зарегистрированы. Это не утверждение об отсутствии любых ошибок сети: намеренный сбой скоринга отдельно вызывает ошибочный ответ.

## Контролируемый сбой и восстановление

Временно переопределён процесс API только в тестовом Compose: обёртка выбрасывает исключение на втором расчёте. Исходники, образ и модель не правились. После сбоя в БД **0 результатов и 2 отправленных сценария**. Участник видит обычное ожидание, организатор — ошибку и «Повторить скоринг». Повтор через UI завершился, участник автоматически получил результат. [Лог проверки](browser-failure-retry.log), [участник](ui-failure-player-mobile.png), [организатор](ui-failure-admin-desktop.png), [результат повтора](ui-retry-result-mobile.png).

Обычный API восстановлен [без fault-overlay](restore-standard-api.log), UI перезапущен. Сессии обеих ролей и результат участника сохранились; организатор создал новую игру. [Лог перезапуска](browser-restart.log).

После создания новой игры осталась вкладка «Результаты», поэтому первый скрипт не нашёл поле цели. При явном выборе «Игра» настройки доступны: это ошибка предположения проверочного скрипта, не исчезновение формы. Изменение цели через мобильный UI воспроизвело **DEP-01**: сервер отклонил её как несовместимую с пакетом. [Лог](browser-admin-settings.log), [форма](ui-admin-settings-mobile.png), [ошибка](ui-admin-save-mismatch-mobile.png).

## Ревью кода и замечания

Изучены ui/nicegui/participant.py, organizer.py, клиент API, обработчики карточек, обновление заголовков, autosave/revision, polling и очистка элементов. Проверки game_poll_races и nicegui_client включены в прогон. Форма использует серверную проверку цепочки; UI не является границей авторизации. Общий экран ожидания при scoring_error — намеренное поведение, не дефект.

### UI-01 · P2 · Ошибка очистки диалога при удалённом клиенте

В серверном логе зафиксированы `Client has been deleted but is still being used` и `ValueError: list.remove(x): x not in list`. Место: **src/aml_workshop_simulator/ui/nicegui/organizer.py:479**, безусловный dialog.delete в завершении confirm; вызов command на строке 493. [Полный стек](ui-runtime-log.log).

Наблюдалось в серии прерванных браузерных проверок диалога подтверждения. Сценарий воспроизведения для изолированной регрессии: открыть подтверждение административной команды, закрыть вкладку до ответа, дождаться удаления клиента. Отдельная повторная минимальная репродукция не выполнена; связь с конкретным закрытием вкладки предполагается по стеку и последовательности проверки. Факт исключения подтверждён, потеря данных и отказ последующих команд не наблюдались. Требуется безопасная очистка диалога с учётом жизненного цикла клиента и отдельный тест.

### TEST-03 · P2 · Устаревшие UI-селекторы

Два теста nicegui_participant_editing/nicegui_forms ждут удалённое «Добавить операцию». Обновить на доступные роли/названия кнопок, сохранить проверку редактирования и отправки. Реальное поведение кнопок проверено browser-editor/browser-results.

### UI-02 · P3 · Сложность сопровождения

participant.py объединяет построение страницы, состояние редактора, polling, отправку и отображение расчётов. Это затрудняет локализацию гонок и изменений оформления. После функциональных исправлений целесообразно выделить компоненты редактора/результатов и управление состоянием. Это замечание к сопровождению, не самостоятельный доказанный пользовательский сбой.

## Пропуски и ограничения

Нет Safari/Firefox, физического мобильного устройства, screen reader, полной клавиатурной проверки, нагрузочного множества UI-сессий и длительного обрыва сети. Перетаскивание/все перестановки и все типы карточек не пройдены вручную в этом браузерном прогоне. Сохранение новых настроек организатора проверено тестами текущего v10, но сквозной Linux UI-сценарий с такими настройками заблокирован DEP-01. Отдельного успешного прогона всех конкурентных случаев на v10 нет.

Первоначальные browser-start/browser-failure/browser-restart содержат таймауты проверочного сценария (скрытый дубликат текста, неотвеченное подтверждение, неверный текст ошибки, прежняя вкладка). Их нельзя считать продуктовым дефектом без повторной диагностики; исправленные проверки и ограничения указаны выше.
