# 2. Скоринг, целостность и совместимость

## Результат

[Тесты слоя](scoring-tests.log): **27 passed, 6 failed**, 79,72 с ([JUnit](scoring-tests.xml)). Актуальный v10-пакет проходит контрольные расчёты и полный API-прогон 25 опубликованных сценариев, включая откат после ошибки, повторный запуск и отсутствие повторного пересчёта. Два падения относятся к legacy v8 (API-01), четыре — к устаревшему mock в тестах закрепления пакетов.

## Проверенные свойства

Ревью пути: canonical_steps → извлечение признаков → три временных окна → CatBoost → калибровка средней вероятности → ресурсный/итоговый балл → транзакционное сохранение → рейтинг. Итог использует вероятность полной точности; SHAP объясняет raw margin каждого окна, не проценты итогового балла. UI сортирует подписанные вклады по убыванию; отрицательный вклад не поднимается наверх только из-за модуля.

[Контрольный прогон](model-probe.log): 25 векторов признаков и прогнозов точно совпали с эталоном. На 15 различных цепочках диапазон вероятностей **0,0009733–0,9998970**. Максимальная невязка `base + сумма SHAP − raw margin`: **3,20e−14**. Изменённый features.json в отдельной копии пакета отклонён загрузчиком. Пакет выпуска и обучающие данные не менялись.

Время 15 расчётов с SHAP на Windows/Python 3.13: **5,064 с суммарно**, медиана **326,24 мс**, максимум **463,64 мс**. Это локальный последовательный инференс, не нагрузочная гарантия Linux-сервера и не время HTTP/БД.

Проверены новые настройки организатора, отклонение несовместимых настроек/подменённого pin, изменённые лимиты покупки и корректный текст превышения. История и цель не входят в признаки текущей модели; редактор не изменяет эту модельную семантику.

[Реальные старые pins](actual-pins.log): четыре архивных игровых пакета выбираются и проверяются корректно. Это не распространяется на отдельный legacy-адаптер v8, для которого воспроизведён API-01.

Атомарность v10 проверена через API: принудительная ошибка на втором сценарии не публикует первую оценку; повторный запуск рассчитывает все 25; вызов после завершения не пересчитывает результаты. Административная ошибка доступна организатору; участнику не передаётся отдельное сообщение о сбое — это согласованное поведение.

## Замечания

### SCORE-01 · P2 · Инструмент выпуска даёт ложное подтверждение при python -O

Место: scripts/package_organizer_settings.py; аналогичный паттерн assert есть в scripts/package_retired_limits.py. Проверки хешей и равенства контрольных прогнозов реализованы assert. При `python -O` они исчезают. Воспроизведение: эталон одного прогноза намеренно заменён на 0,54321; [скрипт завершился с кодом 0 и сообщил Verified 25 identical](optimized-release-check.log). Неверно подтверждённый пакет создан только в .local-run и нигде не запущен. Runtime-проверка хешей модели не отключается; дефект касается достоверности процедуры выпуска. Требуются явные проверки/исключения и регрессия для обычного/оптимизированного Python.

### TEST-02 · P2 · Тесты старых pins используют неполный mock

Четыре падения `test_pinned_game_packages`: SimpleNamespace не содержит release, который теперь читает get_pinned_game_classifier. Реальные пакеты проверены отдельно и проходят. Требуется обновить двойник и сохранить проверки подмены идентичности; не ослаблять runtime-проверку ради mock.

### API-01 · Повторное подтверждение

Два legacy-теста рейтинга/восстановления не проходят из-за несовместимости вложенного v8-адаптера. Причина описана в [FastAPI](01-fastapi.md).

## Границы заключения

Переобучение и повторная полная оценка качества на обучающем/test-датасете не выполнялись. Новые произвольные конфигурации организатора не считаются отдельно валидированным распределением для модели. Контейнер всё ещё содержит прежний пакет (DEP-01), поэтому успешный локальный контроль текущей модели не означает её присутствия в Docker-релизе.
