## Замечания

### ERR-UI-01 — P2: отсутствует специальная подсветка суммы

Воспроизведение: две операции снятия по 100000; нажать «Шаг 2» у превышения наличного лимита. Аналогично три перевода по 80000 и ошибка баланса шага 3.

Ожидается: раскрытие, прокрутка, фокус и временное выделение суммы. Фактически поле получает обычный фокус Quasar, но класс `correction-highlight` не обнаружен в интервале ожидания. Для ошибок с `field=card` этот же механизм успешно работает.

Место: `src/aml_workshop_simulator/ui/nicegui/participant.py:898–920`, `focus_error_step`, и `theme.py:312`. Вероятная причина: реактивное обновление класса поля после focus отменяет прямое добавление класса; причина требует проверки при исправлении. Не выдавать эту гипотезу за установленный факт.

### ERR-UI-02 — P2: ошибка суммы покупок без перехода

Воспроизведение: две покупки по 20000 при лимите 30000. API возвращает `purchase_total_exceeded`, `step_index=2`, `step_id`, `field=amount`, но UI не создаёт кнопку «Шаг 2».

Причина в коде: `participant.py:190–207` определяет наличие кнопки регулярным выражением по тексту сообщения, а не структурированными полями нарушения. Сообщение покупок не начинается со слова «Шаг».

### ERR-UI-03 — P3: двойной знак валюты

В том же сценарии виден текст «Общая сумма покупок превышает 30 000 ₽ ₽». Место: `domain/simulation.py:338`: после `_fmt_money(...)` добавлен ещё один знак валюты. Дополнительно у превышения количества зарплат неудачное согласование «набрано 2 карточек».

## Границы покрытия

- `required_operation_missing` не активируется текущим каталогом: зависимости операций не заданы. Не проверено в браузере с отдельной изменённой конфигурацией.
- `amount_out_of_range` как серверный blocker не достигнут через сохранение: контракт API отвергает такую цепочку с 422, а редактор ограничивает ввод. Проверена именно пользовательская валидация суммы зарплаты; все пять типов отдельно по каждой числовой границе не прогонялись.
- Структурные ошибки (`duplicate_step_id`, неизвестная версия/карточка, несовпадение ссылки, запрещённый канал, недопустимые/отсутствующие параметры) перечислены в `domain/structure.py`. Подмену этих данных и их UI-отображение в этом прогоне не проверяли: обычный редактор формирует ID и значения из разрешённых списков.
- Проверка максимума шагов использовала подготовленные 17 шагов; блокировка добавления 17-го шага самим редактором отдельно не проверена.
- Отрицательное, пустое, дробное значение с лишними знаками и гонки быстрых повторных кликов отдельно не проверены.
- Этот отчёт не подтверждает полноту всех ошибок backend и не заменяет общий аудит UI. Продуктовые исправления не выполнены.
