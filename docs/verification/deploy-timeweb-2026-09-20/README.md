## Эксплуатация

### Формат суммы, 20.09.2026

UI обновлён до `aml-runtime:20260920-amount-format` поверх исходного релизного образа с обоими исправлениями суммы. В заголовках редактируемых и отправленных операций целые суммы отображаются без копеек (`10 000 ₽`), дробные — с двумя знаками (`10 000,50 ₽`). Начальная отрисовка и изменение поля используют один формат. Расчёты и формат итоговых баллов не менялись. Проверено: 10 тестов форматирования/компонентов/навигации ошибок и Ruff. Конфигурация для отката: `deploy/compose.production.yml.before-amount-format`; заменяется только контейнер UI.

### Исправление заголовка суммы, 20.09.2026

После исходного деплоя UI обновлён до `aml-runtime:20260920-amount-heading` через `deploy/compose.production.yml`. Образ наследует проверенный `aml-runtime:20260920`, заменён только `ui/nicegui/participant.py` (SHA256 `fd068e920e1a165fa7af68b3e435f81d907674619911b048340e78cc241db1d3`). Заголовок суммы обновляется обработчиком изменения поля без пересоздания карточки; ноль отличён от пустого значения. API, модель и БД не менялись и не перезапускались.

Проверено: 4 теста (`test_operation_amount_heading.py`, `test_correction_navigation.py`), Ruff, совпадение SHA256 установленного файла, healthy UI, публичный HTTPS health 200. Новый тест проверяет все пять типов операций, дробные суммы, очистку и ноль, неизменность соседних заголовков и элементов карточек. Это симуляция компонентов NiceGUI; отдельный браузерный ввод на production не выполнялся. На Windows тесты запущены с `python -X utf8` для чтения существующих UTF-8 fixtures.

Предыдущая конфигурация сохранена на сервере в `deploy/compose.production.yml.before-amount-heading`. Для отката только этого исправления восстановить её и выполнить `compose up -d --no-build --no-deps --wait ui` с тремя файлами Compose, указанными ниже. Базовый релизный архив и старый образ сохранены без изменений.

```bash
cd /opt/amlplay/releases/20260920
docker compose -f docker-compose.yml -f deploy/compose.image.yml -f deploy/compose.production.yml ps
docker compose -f docker-compose.yml -f deploy/compose.image.yml -f deploy/compose.production.yml up -d --no-build --wait
python3 /opt/amlplay/backup.py
```

Начальная копия: `/opt/amlplay/backups/20260920T013337Z`. Локальная копия находится в `.local-run/deploy-timeweb-20260920/backups/`. Содержит секреты и не должна попадать в Git или публичные отчёты. Автоматическое расписание копирования не настроено.

Старая установка `/opt/amlautosim` и её тома сохранены; все три контейнера `amlautosim-*` остановлены. Для аварийного возврата пилота:

```bash
docker stop amlplay-ui-1 amlplay-api-1 amlplay-db-1
docker start amlautosim-db-1 amlautosim-api-1 amlautosim-ui-1
```

Такой возврат переключает сайт на прежнюю отдельную базу, а не переносит новые данные в пилот. Новые тома удалять нельзя. Для возврата новой установки сначала остановить пилот, затем выполнить приведённый выше `compose up`.

## Границы результата

- Это фактический деплой проверенного release candidate. Незакрытые проверки исследовательского контура и двух тестовых моделей из [отчёта выпуска](../release-2026-09-20/README.md) остаются открытыми.
- Полную игру на публичной БД не запускали, чтобы оставить пользователю чистую установку. Полный маршрут ранее пройден на том же Docker-образе; на сервере проверены загрузка модели, прогнозы/SHAP, вход, состояние БД и перезапуск.
- Здесь проверена читаемость нового dump, но не выполнено отдельное восстановление этой новой копии. Восстановление тестовой БД проверялось на этапе выпуска.
- Мобильный прогон, браузерная консоль, нагрузочные испытания и длительная стабильность WebSocket через балансировщик в этот деплой не входят. Интерактивный вход и переключение вкладки организатора работают.
- Правила сетевого доступа сервера сохранены: UI 8080 опубликован на сервере, API и БД доступны только через loopback/Docker-сеть. Отдельное ограничение origin-порта только IP балансировщика не настроено.
