# Автосохранение: изменения и повторная проверка 2026-09-26

В рабочем дереве поверх `b00a096a9ac54b764bc737aeb53df87e82e1b0e8` сокращено ожидание автосохранения с 1 с до 0,4 с. После preview заново проверяются возраст последней правки и актуальность preview: изменение во время запроса сохраняется только после своей паузы и проверки. Существующие блокировки сериализуют команды; новые правки во время записи остаются dirty для следующего сохранения. Preview по-прежнему выполняется до save; условия submit, компоновка и тексты UI не изменены.

Добавлены гистограммы ожидания автосохранения, preview, записи и времени от серверной обработки изменения до успешной записи той же версии. Последняя не включает доставку статуса клиенту. Основная метрика ниже — полный путь драйвера от события изменения до «Сохранено».

## Методика и происхождение

Измеренный образ: `sha256:d1350d6f064c98c54b47cb7d16d9a7d22b7e79a47e92ed54fa1c745d41473bc9` (`aml-perf:autosave-20260926`). Он содержит незакоммиченный патч поверх указанного SHA; метка Git сама по себе не описывает этот образ. Патч сохранён в `runtime.patch`, SHA-256 изменённого исходника и драйвера — в `summary.json`. Побайтовое совпадение исходника в образе с рабочим деревом проверено отдельно.

Тот же неизменённый Socket.IO-драйвер через nginx, один API worker, пул 5+10, timeout 5 с, одна операция на участника, пауза 3 с между завершёнными правками. По три прогона 45/60 участников, каждый по 120 с активных правок, каждый с новой БД и контейнерами. Начальные вход/подготовка измерены отдельно. Локальный Docker Desktop/Windows; PostgreSQL в tmpfs. Это не production-сервер и не измерение браузерной отрисовки. Полная исходная методика и её ограничения: [до изменений](../perf-2026-09-26/README.md).

Первые четыре прогона завершились до прерывания сессии. Незавершённая попытка 45-r3 не создала итогового JSON и не включена в результаты; её журналы сохранены локально. После проверки отсутствия процесса старый стенд удалён, два последних прогона выполнены заново на том же образе. Поэтому серия не является непрерывным soak; фоновая активность общего хоста не контролировалась.

## Результаты

p95 — nearest-rank по успешным действиям; ошибки учтены отдельно. Сравнение повторов показывает наблюдавшуюся разницу, а не гарантированный выигрыш для любого окружения.

|---:|---:|---:|---:|---:|---:|---|

| 45 | 3 | 2,325 | 1,359 | 1419 | 0 | Пройден |

| 60 | 3 | 2,601 | 1,490 | 1837 | 0 | Пройден |

При объединении успешных правок трёх повторов p95 изменился с 2,135 до 1,452 с для 45 участников (около −32%) и с 2,387 до 1,721 с для 60 (около −28%). Медианы: 1,410 → 0,814 с и 1,475 → 0,988 с соответственно. Это перцентили объединённых выборок, а не среднее трёх перцентилей; они не заменяют критерий прохождения каждого прогона.

Всего после изменения 9610 попыток правки, 9607 успешных, три TimeoutError ожидания UI. Все 45/60 клиентов подключились в каждом прогоне. HTTP 5xx, traceback и признаки pool timeout в сохранённых журналах не обнаружены; опрос метрик без ошибок. Причина таймаутов UI не установлена: текущий драйвер не сохраняет, какое из двух ожиданий статуса завершилось таймаутом. Считать их исправленными или доказанными потерями данных нельзя.

**PERF-01 остаётся открытым:** патч снижает задержку, но не обеспечивает стабильный p95 ≤1,5 с во всех повторах. Двухчасовой soak не проводился. Следующее исследование — задержка периодического таймера, очередь UI, последовательные preview/save и точная диагностика ожидания статуса драйвером.

## Проверки корректности

- 13 unit-проверок таймера и гонок редактора: прошли. Семь новых проверок покрывают объединение быстрых правок, медленный preview, изменение во время preview/save, ревизии и запрет записи при submit/conflict/закрытии. Новые node IDs включены в runtime inventory.
- 18 API-проверок на отдельном PostgreSQL: прошли, включая реальные изменения параметров после autosave и конкуренцию с submit.
- 20 сценариев Firefox/WebKit: прошли. Первоначальные 10 ошибок Chromium вызваны отсутствующим headless-бинарником; соответствующие 10 сценариев повторены на установленном Google Chrome и прошли. Проверены фокус/курсор, восстановление черновика, редактирование, перестановка и отправка на нескольких ширинах экрана.
- Ruff для проекта и runtime-профиля, mypy: прошли. Проверка whitespace diff: прошла.

Отчёты тестов находятся рядом (`autosave-*.json`), включая первоначальные ошибки запуска Chromium. Это целевые регрессии, а не новый полный прогон всех тестов проекта. Изолированные нагрузочные стенды и тестовый PostgreSQL удалены. Развёртывание и публикация не выполнялись.

## Артефакты и повторение

`45-r*.json.gz` и `60-r*.json.gz` содержат полные действия и срезы метрик без учётных данных; `summary.json` содержит настройки, перцентили, ошибки, хэши исходных JSON и исходников. Серверные гистограммы ограничены последними 1024 наблюдениями и могут включать подготовку — нельзя складывать p95 этапов или выдавать их за p95 всей серии.

Для повторения собрать образ из рабочего дерева с данным патчем и полным базовым SHA, затем следовать `tests/load/nicegui_driver/README.md`: новый lab на каждый повтор, `--accounts 45`/`60`, runner `--users 45`/`60 --seconds 120`, прочие настройки по умолчанию. После каждого прогона сохранить результат и остановить lab.
