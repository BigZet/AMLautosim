## Замечания

### UX-01 — сброс выбранного ожидания после перестановки, P2 / требует продуктового решения

1. Создать зарплату первым шагом и входящий перевод вторым.
2. У входящего выбрать ожидание 1 час: заголовок показывает 10:00.
3. Свернуть и переместить входящий на первое место, затем обратно на второе.
4. Фактически заголовок показывает 09:01: прежний час не восстановлен; ресурс времени также изменился.

Для пользователя обратная перестановка выглядит как возврат исходного порядка, но меняет интервал. Желательно сохранять прежнее ожидание в состоянии редактора либо явно показывать его сброс. Требование «у первой операции ожидания нет» соблюдается; дефект бизнес-правил этим наблюдением не доказан.

Предполагаемое место: `participant.py:958` (перестановка → changed), `game.py:52–60` (канонизация интервалов). Снимок итоговой последовательности: [10](10-chain-desktop.png); точный переход 10:00 → 09:01 зафиксирован в интерактивном AX-наблюдении, отдельного парного снимка нет. Повторный воспроизводящий прогон с парными снимками остаётся полезным дополнением.

### ENV-01 — управление Chrome прервано другим расширением

Это ограничение окружения, не дефект AMLautosim. Последний вызов сообщил, что открыто UI другого расширения; дальнейшее управление требует закрыть это окно в Chrome. IAB в доступном наборе браузеров отсутствует. Прежние ограничения Windows-автоматизации определения URL удалось обойти переходом на прямое подключение Chrome, но текущую блокировку обойти нельзя.

2. Подтвердить повторный вход, выполнить создание новой тестовой игры; проверить возврат участника в ожидание.
3. Проверить настоящий browser offline с подтверждёнными и несохранёнными изменениями; вернуть сеть и сверить сохранность.
4. Подтвердить 125% штатными средствами Chrome, проверить ключевые экраны в этом масштабе.
