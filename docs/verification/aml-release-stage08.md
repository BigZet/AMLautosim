Дата: 14 сентября 2026 года. Исполнитель: Codex. База рабочей копии `be4cb32`;
проверены незакоммиченные изменения этапов 01–07. Публикация на сервер не выполнялась.

## Результат

Расширенная игра v8 проходит настройку, запуск, редактирование, автосохранение,
перезагрузку, отправку, расчёт и рейтинг. Старый v7 сохраняет прежние расчёты.
Неизвестные версии отклоняются; снимки не обновляются автоматически.
CatBoost не обучен и не подключён. Этап завершает пакет расширения игры и датасета.

## Браузер, перезапуск и отключение

Проверка выполнена автоматизацией настоящего Chromium, FastAPI, NiceGUI и PostgreSQL,
без подмены транспорта. Сценарий: `.venv/bin/python -u .local-run/stage08/browser.py`.

1. Организатор выбрал расширенные правила, сохранил настройки и начал раунд 2.
2. Два участника зарегистрировались через UI (1440×1000 и 390×844).
3. Начальные цепочки `purchase` и `varied` загружены через настоящий API.
   Через UI изменены сумма покупки на 1 100 ₽, порядок и интервал ожидания.
   Проверены автосохранение и reload с сохранением ID и порядка.
4. Между сохранением и отправкой первого участника контейнеры API/UI пересозданы.
   Секрет NiceGUI и тома сохранены. Вход обеих ролей, полный снимок и черновик
   восстановились; повторный вход не потребовался.
5. При пересоздании включён `EXPANDED_ROUNDS_ENABLED=false`: defaults v8 вернул 409,
   метаданные — только `[7]`. Сохранённый v8 остался доступен для отправки и скоринга.
   Дополнительная мобильная проверка окна «Новая игра» подтвердила отсутствие v8.
6. Оба участника отправили сценарии, организатор запустил скоринг. Сохранённые
   ресурсы совпали с результатами: баланс 6 850 ₽, энергия 8, время 8 и 1,

Восстановленные БД и том запущены отдельными API/UI на 58210/58211.
Сверены полный ответ раунда с оригиналом, вход существующего организатора и

## Исправления и неудачные промежуточные проверки

- Тестовый Dockerfile сначала использовал основной build context, где
  `requirements-dev.txt` намеренно исключён. Для тестового образа подготовлен
  отдельный минимальный контекст; runtime `.dockerignore` не ослаблялся.
- Совместный запуск unit/API в стандартном режиме pytest дал пять ошибок
  `import file mismatch` из-за одноимённых файлов. Повтор с `--import-mode=importlib`
  прошёл полностью; команда внесена в `tests/README.md`. Проверки не отключались.
- Первая проба резервного копирования шла одновременно с мобильным входом:
  игровая информация совпала, но изменились sessions/users. Согласованная копия
  повторена при остановленных API/UI, после чего совпали все таблицы.
- Проверка восстановленного интерфейса первоначально искала участников на вкладке
  «Игра». Сценарий исправлен: открыть «Результаты» и дождаться строк участников.
- Одна дополнительная команда проверки баланса была прервана пересозданием API
  (137); после готовности контейнера повторена успешно.
- Финальная служебная проверка сначала ожидала имя статуса `scored`; контракт
  использует `completed`. Проверка приведена к контракту и повторена успешно.
- Историческое падение теста входящей формы «пять списков вместо четырёх» устранено
  в предшествующих этапах. В текущие полные прогоны входит активная проверка формы.
- Исправлено устаревшее утверждение, что скоринг v8 не подключён к обычной игре.
  API, данные, UI, проведение игры и скоринг описывают фактическую поддержку v8
  и отделяют её от офлайн-рубрики завершённого этапа 07.

## Ограничения

Мобильная проверка — viewport Chromium, не физическое устройство. Начальные
цепочки загружались API, а не полностью набирались карточками. Проверялась
локальная Linux arm64-сборка; публичный сервер, HTTPS и нагрузка этим этапом
не проверялись. Есть два предупреждения устаревания зависимостей Starlette/AnyIO
на Python 3.13; ошибок зависимостей и падений тестов нет.

Согласование датасета: 12 примеров без слепой оценки по решению пользователя,
окончательные правки делегированы исполнителю. Технический валидатор не выдаётся
за независимую человеческую проверку. Три группы шаблонов, постоянный целевой
оборот и оставшиеся расхождения с отдельными оценками описаны в
[отчёте этапа 07](aml-dataset-stage07-final.md). Синтетическая рубрика не подтверждает
эффективность банковского AML. Обучение и подключение CatBoost — следующий отдельный этап.
