# Этап 04: покупки и целевой оборот

Дата: 13 сентября 2026 года. База рабочей копии `be4cb32`; изменения не закоммичены.

## Реализация

Добавлена карточка `purchase` v1 в `config/expanded_operations.json`. Seed хранит
пять карточек в существующей таблице, но каталог обычной игры v7 и её начальные
операции по-прежнему содержат четыре. V7 не принимает конфигурацию с покупкой.
Новых таблиц и миграций нет; ранее сохранённые снимки не переписываются.

Новые снимки v8 включают `behavior.purchases` с версией `purchase-policy-v1`.
Если блока нет/null, прежний тестовый контракт v8 сохраняет расчёты этапа 03;
карточка покупки в таком снимке запрещена.

Параметры версии v1 фиксированы: 1 000–20 000 ₽, максимум три покупки, не более
30 000 ₽ суммарно, энергия 1, базовое время 1, комиссия 0. Ожидание списывается
отдельно по временной шкале. Переопределение этих параметров отвергается. Покупка
выбирает получателя типа merchant; категория выводится из его записи. Ручная
категория, произвольная сторона и характеристики в шаге не принимаются.

Пределы покупки действуют вместе с прежними ограничениями на деньги, шаги,
ресурсы и длину серии одинаковых операций. Например, три покупки допустимы по
количеству, но три подряд могут нарушать общий предел серии; базовый баланс
и ограничения ради нового действия не изменялись.

## Оборот, результаты и риск

В ресурсном snapshot этапа 04: `schema_version=7`,
`ruleset_version=expanded-rules-stage04-v1`. Это версия **результата**; версия
контракта раунда остаётся 8.

- `totals.gross_outflow` — все суммы списаний без комиссии, включая покупки.
- `totals.target_outflow` — только переводы по карте и снятия, засчитываемые в цель.
- `totals.purchase_outflow` — сумма покупок.
- `totals.fees` — комиссии отдельно; баланс уменьшен на суммы списаний и комиссии.
- `objective.reached` и blocker недостигнутой цели используют только целевой оборот.
- В `limits` видны сумма и количество покупок; превышения возвращают нарушения.
- В `per_step.purchase` сохраняется производное представление торговой стороны и категории. В исходных шагах остаётся только ссылка на сторону.

Оба показателя проходят через preview, сохранение, отправку, скоринг и чтение
результата. Редактор, экран отправленного сценария, ресурсная сводка и
административный просмотр показывают общие списания и зачёт в цель раздельно.
Подпись «Всего потрачено (без комиссий)» сопровождается отдельной суммой комиссий.
Прежние ответы v7 не получают новых полей.

Для временного сравнительного скоринга `expanded-scoring-stage04-v1` покупки
исключены из факторов и знаменателя усреднения. Это устраняет автоматическое
снижение среднего риска при добавлении дешёвого шага. Связи между финансовыми
операциями анализируются без разрыва покупкой, а фактические прошедшие минуты
между ними сохраняются. Для этих промежутков: 1 минута — rapid, меньше 60 —
normal, от 60 — spaced. Добавленная в конец покупка не меняет риск цепочки.

Изменение реальных временных промежутков или времени суток может изменить риск;
это эффект времени, а не защитный вклад покупки. В ресурсном рейтинге знаменатель
для доли комиссий использует целевой оборот: покупка без комиссии не улучшает
эту долю. Этот сравнительный расчёт не является согласованной рубрикой датасета.

контроль старых золотых сценариев.

Тест API выполнил полный путь смешанной цепочки: freeze → preview → save → reload
