Измерен текущий код `b00a096` без изменений runtime. Локальный Docker Desktop на Windows; Linux-контейнеры, Docker: 12 CPU, 33 590 730 752 байт RAM. Это не измерение production-сервера.

Образ: `sha256:bd03477ca0643709f964b136fb9ecf1165fc24364d861c721d0cb44320006025`.

## Методика

По три независимых прогона для 45 и 60 участников, чередование 45/60, по 120 секунд активных правок. Перед каждым прогоном новая БД и новый набор контейнеров; вход и подготовка отдельны от правок. Один API worker, пул 5+10, timeout 5 с, один процесс NiceGUI. PostgreSQL в tmpfs, как в штатном `deploy/compose.smoke.yml`.

Штатный `tests/load/nicegui_driver/runner.py`: HTTP/cookie и Socket.IO через nginx; изменение суммы одной операции, ожидание «Сохранено», затем пауза 3 с. Одновременность входа 5. Это замкнутый сценарий: при замедлении приложения снижается частота правок. Он не измеряет DOM/paint, цепочки из 8/16 операций, массовый вход, скоринг или двухчасовой soak. Начальная подготовка прогревает путь preview/save, отдельного длительного прогрева нет.

p95 рассчитан методом nearest-rank по успешным действиям; ошибки приведены отдельно. Метрика edit включает debounce автосохранения. Канарейка — HTTP `/health/live` через nginx.

## Диагностические наблюдения

Всего 8 450 попыток правки; 8 446 успешных, 4 TimeoutError ожидания UI (по два в 45-r2 и 60-r2). Все 45/60 клиентов подключились в каждом прогоне. HTTP 5xx, исключений и pool timeout в сохранённых журналах контейнеров не обнаружено; опрос метрик прошёл без ошибок. После таймаутов клиенты продолжали успешные правки. В 45-r2 счётчик успешных PUT равен числу подготовок плюс попыток правок (1 267), но это агрегат, не доказательство сохранения каждого конкретного значения.

В текущем коде `ParticipantScreen.tick` запускается раз в 0,3 с, ждёт возраста изменения 1 с перед save и выполняет preview перед save. Возраст вычисляется до ожидания preview. Эти ожидания входят в edit; измеренные API-времена не покрывают весь путь. Точной трассировки по этапам одного действия пока нет, поэтому вклад каждого источника задержки и причина четырёх таймаутов не установлены. Штатный драйвер не сохраняет, на каком из двух ожиданий статуса возник TimeoutError.
