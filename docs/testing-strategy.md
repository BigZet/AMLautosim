# Проверка текущего FastAPI

Команды запуска и устройство фикстур: [tests/README.md](../tests/README.md).

Текущий набор заменяет тесты старой архитектуры. Проверки идут через HTTP-контракты
FastAPI и PostgreSQL 16, отдельные тесты игрового движка выполняются без БД.
Alembic применяется к новой временной базе при каждом запуске набора.

Основные инварианты:

- одна текущая игра; перезапуск удаляет игровые данные, сохраняя учётные записи;
- конфигурация редактируется только до старта;
- участник восстанавливает сохранённую цепочку после обновления страницы;
- финальная отправка не требует предварительного сохранения;
- UUID команды обеспечивает повтор после потери ответа, ревизия защищает от старой вкладки;
- невалидная отправка не меняет сценарий и не расходует попытку;
- при закрытии приёма неотправленные цепочки удаляются;
- сбой скоринга откатывает оценки, но оставляет приём закрытым; расчёт можно повторить;
- чтение состояния не блокируется расчётом и согласованно получает сценарий и место;
- лидерборд доступен после входа и завершения расчёта; места совпадают с административным
  представлением, заблокированные участники видны только администратору без места.

Конкурентные проверки используют потоки, барьеры и управляемую задержку скоринга,
с ограниченным ожиданием и освобождением задержки в `finally`.

Streamlit, браузерные сценарии, нагрузка на 50 участников и CatBoost остаются
отдельными этапами. Прохождение этого набора подтверждает поведение backend,
но не заменяет эти проверки.
