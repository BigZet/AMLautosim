# Принятые решения

Текущая архитектура — модульный монолит с двумя процессами: FastAPI и NiceGUI.
Состояние игры хранится в PostgreSQL 16; UI использует серверное состояние NiceGUI.

- Одна текущая игра, один сценарий на участника, одна окончательная отправка.
- Сервер отвечает за доступ, валидацию, ресурсы, разрешения действий и рейтинг.
- Настройки раунда включают полный снимок карточек; после старта неизменяемы.
- Денежные вычисления используют Decimal; JSON передаёт денежные значения строками.
- Конкурентные команды защищены блокировками, ревизиями и UUID повторов.
- Закрытие приёма фиксируется отдельно от скоринга. Сбой допускает повтор расчёта,
  но не открывает приём заново.
- Истории игр, шаблонов, ручных оценок и отдельной команды закрытия приёма нет.
- UI передаёт API-сессию заголовком отдельно для каждого запроса; входы двух ролей
  изолированы. Сырой credential хранится на сервере, в cookie — идентификатор UI.
- Локальные изменения и pending-команды UI защищены от запоздалых ответов,
  смены пользователя, вкладки и игры. Неопределённый исход команды повторяется
  с исходным UUID, а конфликт ревизии требует загрузки актуального состояния.
- Один процесс NiceGUI без reload. Docker запускает приложения непривилегированно;
  код доступен только для чтения, данные размещены в отдельных томах.
- CatBoost сохранён как отложенный эксперимент. Текущий расчёт детерминированный.
- Реверс-прокси и HTTPS будут подготовлены отдельным этапом.
