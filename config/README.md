# Конфигурация симулятора

Настраиваемые игровые значения вынесены в JSON. В Python остаются алгоритмы,
структура контрактов, переходы состояний и математические инварианты.

| Файл | Назначение |
| --- | --- |
| `base_round.json` | Базовые ресурсы, цель, ограничения, квоты, операции, пороги риска и веса оценок |
| `operations.json` | Суммы, комиссия, энергия, время, лимит карточек `max_occurrences`, зависимости и каналы |
| `parameters.json` | Поля карточек, варианты, базовые значения, дополнительные затраты и факторы риска |
| `channels.json` | Каналы и их подписи |
| `resource_rules.json` | Минимальное время операции, поправки канала, темпа и суммы |
| `risk_rules.json` | Коэффициенты временного скоринга |
| `limits.json` | Общие верхние границы входных значений API |
| `bootstrap.json` | Название первой игры |
| `editor_labels.json` | Подписи настроек редактора NiceGUI |
| `synthetic_data.json` | Воспроизводимые шаблоны примеров с текущими карточками для будущей модели |

## Применение

Файлы читаются при запуске процесса. Seed обновляет каталог; новый раунд получает
полный снимок карточек и настроек. Администратор меняет условия только в `draft`.
Запуск фиксирует настройки. Изменение файлов не меняет уже сохранённый снимок.
Шаблонов администратора и истории игр нет.

После правки файлов остановить API/UI, выполнить seed и запустить приложения.
Для применения новой базы настроек создать новую игру через restart.
Текущий каталог использует `incoming_transfer`. Снимки старых форматов
не поддерживаются. Входящие переводы не расходуют наличную квоту.
`AML_GAME_CONFIG_DIR` позволяет указать другой полный набор файлов.

Одна карточка — одна транзакция. Три выполнения операции требуют трёх карточек.
`max_occurrences` ограничивает их общее количество по типу, `max_identical_steps`
— длину серии подряд. В базовой конфигурации допустима серия из двух карточек,
если выполнены остальные условия. Каждая отдельно расходует ресурсы и квоты.

Затраты операции: базовые энергия/время плюс затраты выбранных параметров;
к времени добавляются поправки канала, темпа и суммы, затем применяется
`minimum_time_cost`. Суммы и коэффициенты записываются десятичными строками.
Комиссия `"0.010000"` означает 1%. Нулевая квота запрещает оборот категории,
отсутствие ключа отключает её. Веса каждой группы должны давать в сумме 1.

Участник видит сумму и только объявленные поля конкретной карточки. Зарплата
имеет только основание дохода и пустой контекст; остальные поля перечислены
в [BALANCE.md](BALANCE.md). Канал существует только у карточек с непустым
`channels`. `default_visible_params` задаёт полный порядок полей, а сохранённый
`operations[].visible_params` формируется из контракта сервером. `defaults`
не принимается: скрытых значений нет.

`amount_adjustment` в ресурсных и рисковых правилах задаёт поправку суммы:
от 60 000 ₽ включительно +1 времени и −5 риска. Документов в модели нет.
`requires_card_code` требует предшествующую операцию указанного типа.

Проверяются формат, диапазоны, ссылки на карточки и допустимые параметры.
Достижимость и компромиссы базового баланса проверяются отдельно:
`python -m scripts.check_game_balance`. Обоснование настроек и контрольные
прохождения — в [BALANCE.md](BALANCE.md). Это проверка выбранных маршрутов,
а не поиск глобально оптимального сценария.

Старая БД не обновляется этой начальной миграцией. Текущая схема рассчитана
на чистое развёртывание. Параметры входа и сессий находятся в `.env` и
`core/config.py`, поскольку они не относятся к игровым механикам.

## Расширенные карточки v8

`expanded_operations.json` хранит отдельную карточку `purchase` v1 с фиксированными
параметрами этапа 04. Seed записывает её в общую таблицу вместе с четырьмя прежними
карточками. Каталог обычной игры v7 остаётся прежним; покупка доступна
в конфигурации v8 с `behavior.purchases`.
Параметры этой версии не допускают переопределений. Выпуск `expanded-game-v1` после этапа 06 доступен новым раундам.

`expanded_behavior.json` содержит исходный профиль, каталог сторон и историю.
При создании нового раунда начало и события сдвигаются согласованно, затем
фиксируются в JSON-снимке. Общий валидатор проверяет базовый и расширенный defaults.
Для воспроизводимых примеров расширенного баланса:
`python -m scripts.check_expanded_balance`.

Создание новых расширенных раундов регулирует серверная настройка
`EXPANDED_ROUNDS_ENABLED` (по умолчанию true). false не меняет и не отключает
ранее сохранённые выпущенные раунды. Seed по-прежнему создаёт базовый v7.


### Отправитель зарплаты и входящего перевода

Новые расширенные раунды содержат `behavior.sender_policy = "separate-employer-v1"`.
Сторона с категорией `employer` доступна отправителем только для зарплаты;
обычный входящий перевод её не принимает. Другие организации могут отправлять
обычный перевод, но не зарплату. Сервер, редактор и история используют одно правило.
Исходящий перевод работодателю разрешён. Старые снимки без `sender_policy`
читаются и рассчитываются по прежним правилам; их политика не обновляется автоматически.
