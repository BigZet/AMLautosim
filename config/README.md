# Конфигурация симулятора

Все настраиваемые игровые значения находятся здесь. В Python остаются алгоритмы,
структура API, правила жизненного цикла и математические инварианты (например,
денежная точность до копейки и шкала результата 0–100). Исторические миграции и
тестовые примеры намеренно сохраняют свои исходные значения.

| Файл | Назначение |
| --- | --- |
| `base_round.json` | Базовый раунд: ресурсы, цель, ограничения, квоты, операции, пороги риска, веса лидерборда |
| `operations.json` | Каждая операция: комиссия, энергия, время, риск, суммы, повторы, зависимости, каналы, видимые параметры |
| `parameters.json` | Параметры операций, варианты выбора, значения по умолчанию и дополнительные затраты/риск каждого варианта |
| `channels.json` | Допустимые каналы и их названия |
| `resource_rules.json` | Минимальное время шага, время обслуживания по каналам, поправки за темп повторов и документы |
| `risk_rules.json` | Коэффициенты риска суммы, повторов, контекста, документов и последовательности; размер объяснения |
| `limits.json` | Общие верхние границы редактора и API: ресурсы, суммы, число шагов, повторы, стоимость, видимые параметры |
| `bootstrap.json` | Название первого демонстрационного раунда |
| `synthetic_data.json` | Настройки и шаблоны генератора учебного датасета, категории признаков |
| `editor_labels.json` | Подписи дополнительных настроек в админке |

## Как применяются настройки

1. API проверяет конфигурацию при запуске. Отсутствующий файл, неверный JSON,
   повторяющийся ключ и некорректные игровые значения вызывают ошибку;
   встроенной резервной таблицы цен в Python нет.
2. Seed читает каталог из файлов. Админка получает базовую конфигурацию через
   `GET /api/v1/admin/game-config/default` и каталог через API.
3. При создании раунда сервер сохраняет его ресурсы, ограничения, коэффициенты
   и полный снимок карточек в `rounds.game_config`. Значения операции из
   `operations[]` имеют приоритет над значениями карточки этого снимка.
4. Каталог участника, предварительный расчёт, сохранение, отправка и итоговый
   скоринг используют один снимок. Изменение исходных файлов или пресета
   **не меняет уже созданный раунд**. Изменить его игровые условия можно в
   админке, пока он является черновиком.
5. Пресеты администратора сохраняются в PostgreSQL, а не переписывают файлы.
   При создании раунда из пресета настройки копируются. Повторный seed не
   перезаписывает отредактированный базовый черновик.

Денежные суммы и десятичные коэффициенты рекомендуется записывать строками:
`"150000.00"`, `"0.005000"`. Комиссия задаётся долей: `"0.010000"` = 1%.
Нулевая квота запрещает оборот категории; отсутствие её ключа отключает квоту.
Веса неотрицательны и в каждой группе должны в точности давать 1.

Расчёт стоимости: базовые энергия/время умножаются на число повторов;
надбавки выбранных параметров добавляются один раз за шаг. К времени также
добавляются поправки канала, темпа и документов; затем применяется
`minimum_time_cost`. Поэтому нулевая базовая стоимость времени не означает
нулевой итог, пока минимальное время или надбавки больше нуля.

Скрытые параметры можно закреплять через `operations[].defaults` и редактор
админки. Для видимых параметров закрепление запрещено: их выбирает участник.
Зависимость `requires_card_code` требует указанную операцию раньше в цепочке.

## Обновление файлов

Файлы читаются один раз на процесс. В Docker Compose папка подключена к API и
интерфейсам только для чтения. После изменения настроек перезапустите сервисы:

```bash
docker compose restart api admin play
```

При первом обновлении кода требуется `docker compose up -d --build`.
Seed при старте API обновит каталог для новых раундов. Существующие раунды
сначала получают полный снимок прежних карточек, поэтому изменение каталога
не меняет их расчёты. В первом обновлении старые раунды без коэффициентов
получают исходные значения из файлов этой версии; сначала установите эту
версию с её неизменёнными файлами и только затем меняйте баланс игры.

При локальном запуске можно задать `AML_GAME_CONFIG_DIR` как абсолютный путь
к другому полному набору файлов. Эта переменная должна быть передана процессу
API, seed и админки одинаково. После изменения состава каналов/вариантов
контекста обновите соответствующие таблицы стоимости и риска — неполный набор
отклоняется проверкой.

## Проверки

```bash
python -m pytest tests/unit/test_file_configuration.py -q
python -m pytest tests/integration/test_configuration_application.py -q
```

Первый набор проверяет применение действительно изменённых файлов в отдельном
процессе и сохранение настроек редактором. Второй проверяет полный путь через
API до итогового скоринга, защиту снимков и повторный seed на тестовой БД.

`limits.json` задаёт глобальные границы входных запросов, а `channels.json` и
варианты общего контекста — словарь значений API. Это ограничения всей
установки, а не отдельного раунда. Не уменьшайте глобальные границы ниже
параметров сохранённых раундов и не удаляйте используемые ими значения словаря.
Для ограничения конкретного раунда меняйте его `operations` и `constraints`;
для отключения канала у новой карточки меняйте `operations.json`, сохранив сам
канал в общем словаре. Дополнение словаря требует дополнить таблицы коэффициентов.

Параметры сессий и блокировки входа остаются в `.env` / `core/config.py`;
Compose передаёт их API явно. Они не являются игровыми коэффициентами.
