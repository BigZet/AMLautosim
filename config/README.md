# Конфигурация симулятора

Настраиваемые игровые значения вынесены в JSON. В Python остаются алгоритмы,
структура контрактов, переходы состояний и математические инварианты.

| Файл | Назначение |
| --- | --- |
| `base_round.json` | Базовые ресурсы, цель, ограничения, квоты, операции, пороги риска и веса оценок |
| `operations.json` | Суммы, комиссия, энергия, время, лимит карточек `max_occurrences`, зависимости и каналы |
| `parameters.json` | Поля карточек, варианты, базовые значения, дополнительные затраты и факторы риска |
| `channels.json` | Каналы и их подписи |
| `resource_rules.json` | Минимальное время операции, поправки канала, темпа и документов |
| `risk_rules.json` | Коэффициенты временного скоринга |
| `limits.json` | Общие верхние границы входных значений API |
| `bootstrap.json` | Название первой игры |
| `editor_labels.json` | Подписи настроек для будущего редактора UI |
| `synthetic_data.json` | Воспроизводимые шаблоны примеров с текущими карточками для будущей модели |

## Применение

Файлы читаются при запуске процесса. Seed обновляет каталог; новый раунд получает
полный снимок карточек и настроек. Администратор меняет условия только в `draft`.
Запуск фиксирует настройки. Изменение файлов не меняет уже сохранённый снимок.
Шаблонов администратора и истории игр нет.

После правки файлов перезапустить API и выполнить seed для обновления каталога.
Для применения новой базы настроек создать новую игру через restart.
`incoming_transfer` заменяет `cash_deposit` в новом каталоге; старые раунды
продолжают использовать свои снимки. Входящие переводы не расходуют наличную квоту.
`AML_GAME_CONFIG_DIR` позволяет указать другой полный набор файлов.

Одна карточка — одна транзакция. Три выполнения операции требуют трёх карточек.
`max_occurrences` ограничивает их общее количество по типу, `max_identical_steps`
— длину серии подряд. В базовой конфигурации допустима серия из двух карточек,
если выполнены остальные условия. Каждая отдельно расходует ресурсы и квоты.

Затраты операции: базовые энергия/время плюс затраты выбранных параметров;
к времени добавляются поправки канала, темпа и документов, затем применяется
`minimum_time_cost`. Суммы и коэффициенты записываются десятичными строками.
Комиссия `"0.010000"` означает 1%. Нулевая квота запрещает оборот категории,
отсутствие ключа отключает её. Веса каждой группы должны давать в сумме 1.

`operations[].defaults` закрепляет скрытые параметры. Видимые параметры выбирает
участник; UI создаёт карточки с базовыми значениями. `requires_card_code` требует
предшествующую операцию указанного типа.

Проверяются формат, диапазоны, ссылки на карточки и допустимые параметры.
Достижимость и компромиссы базового баланса проверяются отдельно:
`python -m scripts.check_game_balance`. Обоснование настроек и контрольные
прохождения — в [BALANCE.md](BALANCE.md). Это проверка выбранных маршрутов,
а не поиск глобально оптимального сценария.

Старая БД не обновляется этой начальной миграцией. Текущая схема рассчитана
на чистое развёртывание. Параметры входа и сессий находятся в `.env` и
`core/config.py`, поскольку они не относятся к игровым механикам.
